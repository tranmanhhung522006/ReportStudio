# Report Studio — v1.1 Cloud Ready

Local-first formatting workspace for academic and business reports. No account required. PostgreSQL history is optional locally.

## Run on Windows

```powershell
git clone https://github.com/tranmanhhung522006/ReportStudio.git
cd ReportStudio
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe server.py
```

Open http://127.0.0.1:8765. On macOS/Linux use .venv/bin/python instead.

## Workflow

1. Select a DOCX report. Optionally paste an outline with numbered headings.
2. Import requirement PDF/DOCX/TXT or paste text. Extract rules and review evidence before applying.
3. Adjust formatting settings, analyze report, and review heading levels.
4. Run quality audit on original; export a formatted DOCX or render PDF preview.
5. Open output in Word and review fields, page numbers, references and layout. Update TOC/caption fields selectively (F9), not citation fields.

## PDF preview

Install LibreOffice locally. The app invokes soffice using an isolated temporary profile. LibreOffice layout can differ from Word; PDF preview is not a Word-native renderer. Scanned requirement PDFs need OCR externally.

## Optional AI

Set OPENAI_API_KEY in your shell, optionally OPENAI_MODEL, before starting. AI sends requirement text only after explicit consent. API billing is separate from ChatGPT Plus. Never commit credentials. Local parsing is default.

## Safety and scope

Original DOCX is never overwritten. Existing complex fields, hyperlinks and objects are protected conservatively; integrity checks compare selected XML objects and embedded assets before export. This is not a certification of EndNote compatibility or all document contents. Test on a backup. Existing captions with fields are preserved; the app renumbers recognizable plain-text captions, does not invent captions, and does not update cross-references automatically. APA/Harvard/IEEE reference section audit is advisory, not automatic reference conversion. Quality score is based on supported checks, not an academic grade. Page numbering currently targets primary footers. Existing complex numbering and sections require review. AI extraction and OCR are not required for basic use.

## Tests

```bash
python -m unittest discover -s tests -v
```

GitHub Actions runs the regression suite on pushes and pull requests. Do not expose the local HTTP server to the internet.

## Deploy on Render + Neon

1. Create a Neon project and copy its pooled PostgreSQL connection string (keep SSL enabled).
2. In Render choose New > Blueprint, connect this repository and apply render.yaml. Supply DATABASE_URL when prompted. SECRET_KEY and CLEANUP_TOKEN are generated by Render.
3. Alternatively create a Python Web Service on the Free plan:
   - Build: pip install -r requirements.txt
   - Start: gunicorn production:app --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120
   - Health check: /health
   - Set DATABASE_URL and a persistent random SECRET_KEY of at least 32 characters.
   - ENABLE_PDF=0 and ENABLE_AI=0 initially.
4. Open the assigned Render URL. Export a DOCX with history enabled, refresh Recent files, download it again and test deletion.

No manual schema setup is required. The application creates reportstudio_exports on first database access. Keep credentials in Render Environment, never in Git.

### Retention and privacy

Only formatted DOCX exports opted into history are stored. Files become inaccessible 24 hours after creation. A background cleanup runs every 15 minutes while the process is awake; history queries and new saves also remove expired rows. Free Render sleep can delay physical deletion. For independent scheduled deletion, run cleanup.py with DATABASE_URL from an external scheduler, or POST /api/cleanup with Authorization: Bearer CLEANUP_TOKEN and X-ReportStudio: 1. Database backups, WAL and provider retention may retain deleted data beyond application expiry; this is not guaranteed secure erasure.

Limits: 5 MB per saved file, 5 files and 20 MB per browser session, 100 MB total active payload. These are payload quotas, not PostgreSQL disk usage guarantees. The original upload is not retained. History uses a signed session cookie; clearing cookies or using another browser loses access. Do not rotate SECRET_KEY unless you intend to invalidate sessions. Download important documents locally before expiry.

### Optional PDF and AI

The free native Python deployment disables PDF and cloud AI. To enable PDF, use the Dockerfile on a Docker web service and set ENABLE_PDF=1; LibreOffice may exceed free-tier memory, so test before enabling. To enable AI, set ENABLE_AI=1 and OPENAI_API_KEY; API fees are separate and the in-memory rate limit is not a hard global spending cap. Leave AI disabled for anonymous public use unless you implement stronger authentication and billing safeguards.

### Local production smoke test

Set SECRET_KEY to a random value, optionally DATABASE_URL, then run:
```
flask --app production run --port 8765
```
The original python server.py still runs without a database. Production API regression tests use mocked storage; live Neon integration and deployment must be verified separately.
